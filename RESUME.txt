LATEST (Day 9 — live feedback + Groq + tracking fixes)
-----------------------------------------------------
1. FIXED the main bug that stopped word highlighting: browser sent float32
   PCM but the server decoded it as int16 -> garbage into whisper. Now:
   - frontend sends 16-bit PCM + explicit "format":"i16" (half the bandwidth)
   - backend asr.pcm_bytes_to_f32() decodes by declared format (i16/f32),
     no format guessing (guessing was fragile — int16 bytes can look like f32)
   - fmt is threaded through app.py -> engine.py -> asr.py (local + Groq)
2. Groq cloud transcription enabled (GROQ_API_KEY in config.env):
   feedback now ~0.75s through the tunnel instead of 3-4s local CPU.
   Same key also set in /home/mbi/lx.cd.helper/.env and as the GitHub
   Actions secret GROQ_API_KEY for the EC2 deploy.
3. Fixed 3 tracking bugs:
   - engine no longer jumps to the FIRST line when confidence is low
     (stays on current line; emits nothing when no line established yet)
   - tracker only scores the 5-line window once a line is known, so a
     repeated word on a far line can't yank the reader backwards
   - comparer does a right-to-left pass so a repeated word aligns to its
     LATER occurrence instead of the first (was wrongly marked missing)
4. 4 new tests (55 total): pcm_bytes_to_f32 int16/f32 + bad length, sine
   round-trip, repeated-word alignment, low-confidence no-jump, window stays.

PIPELINE
--------
Mic -> 48k -> FIR low-pass 16k -> RMS gate -> 2.5s chunk -> int16 PCM
  -> socket audio_chunk -> RMS gate -> Groq whisper-large-v3-turbo (fast)
  -> current+next line prompt -> normalize -> tracker (line, 5-line window)
  -> comparer (words, repeat-aware) -> feedback -> Mushaf UI highlights
